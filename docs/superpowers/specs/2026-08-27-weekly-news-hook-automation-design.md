# 주간 속보 훅 자동화 설계

- 날짜: 2026-08-27
- 계기: 홈 랜딩의 [NewsHook.tsx](../../../web/components/editorial/NewsHook.tsx)는 2026-07-21 신진서-카타고 대국을 다룬 **수동 작성·일회성** 배너([2026-07-21-shin-jinseo-katago-traffic-design.md](2026-07-21-shin-jinseo-katago-traffic-design.md) 레버 3)다. 사용자 요청. "속보는 최신 뉴스를 활용하여 마케팅 문구를 뽑고, 1주일에 1번 업데이트"— 이를 상시 자동화 파이프라인으로 승격한다.
- 목표: 바둑·프로기사·AI-vs-인간 대국 관련 화제성 뉴스를 매주 탐색해, 발견 시 홈 히어로 훅 문구를 최신화하고 `/game/new`(또는 원클릭 시작) 전환으로 연결한다.

## 전략 통찰 (2026-07-21 스펙에서 계승)

뉴스 키워드 자체는 대형 언론이 지배해 정면 검색 노출 경쟁은 무의미하다. 실효 있는 표적은 뉴스가 만드는 **하류 검색·방문 의도**를 대국 시작 전환으로 잇는 것이다. 이 통찰은 그대로 유지하고, 계기가 될 만한 뉴스가 새로 생길 때마다 수동 개입 없이 갱신되도록 자동화한다.

**정확성 원칙(불변)**. 실제 인물·실제 경기 결과를 다루므로 사실을 정확히 서술하고 과장하지 않는다. 이 원칙이 아래 모든 안전장치의 근거다.

## 범위 밖 (Non-goals)

- 뉴스 도메인을 바둑·프로기사·AI 대국 밖(일반 AI 산업 뉴스 등)으로 넓히지 않는다.
- 글로서리·FAQ 콘텐츠 파이프라인(`content-draft`)을 수정하지 않는다 — 완전히 별도 job.
- 과거 훅 이력을 보여주는 아카이브 UI를 만들지 않는다(YAGNI) — 최신 1건만 유지.

## 아키텍처

### 파이프라인 (신규 job — `content-draft`와 병렬, 독립)

launchd가 주 1회 헤드리스 Claude를 실행하는 기존 오케스트레이터/content-draft 패턴을 그대로 따른다.

1. **뉴스 탐색** — WebSearch 도구로 최근 7일 이내 "바둑 프로기사 AI 대국" 계열 검색. 검색 결과를 사이트 톤·정확성 원칙에 비춰 스스로 평가한다.
2. **판정(게이트)** — 아래 세 조건을 모두 만족하는 항목이 있을 때만 다음 단계로 진행한다.
   - 검증 가능한 출처 URL이 있다(대형 언론·바둑 매체·공식 발표 등).
   - 바둑·프로기사·AI-vs-인간 대국 범위 안이다.
   - 지난주 게시한 것과 동일 사건이 아니다(`web/content/news-hook.json`의 기존 `source_url`과 대조).
   조건을 만족하는 항목이 없으면 **이번 주는 현재 문구를 그대로 유지**하고 종료한다. 이 도메인 뉴스는 몇 주~몇 달에 한 번만 나올 수 있으므로, 대부분의 주에 "변경 없음"이 정상 결과다. 억지로 소재를 만들어내지 않는다.
3. **문구 생성** — 발견한 사실을 한국어 마케팅 톤(기존 NewsHook 문체: kicker/body/guide 3단 구성)으로 **직접 서술**한다. 기사 원문을 인용하지 않고 사실만 자기 문장으로 재구성한다. `source_url`을 프론트매터에 남긴다.
4. **사실검증 서브에이전트** — `korean-copy-qa`와 동일한 형태의 별도 `Agent` 호출로, 생성된 본문의 사실 주장이 `source_url` 페이지 내용과 실제로 부합하는지만 검증한다(언어 자연스러움은 이 단계의 관심사가 아니다). 불일치·불확실 판정이면 게시하지 않고 기존 문구를 유지한 채 사유를 로그에 남긴다.
5. **게시** — 통과하면 `web/content/news-hook.json`을 갱신하고 커밋 + `main` push. 재빌드·재기동 불필요(아래 렌더링 방식 참조).

### 저장·렌더링 — 정적 i18n에서 동적 콘텐츠 파일로 전환

현재 NewsHook 문구(`home.newsHook.*`)는 `web/lib/i18n/ko.json`·`en.json`에 박혀 있어 Next.js 빌드에 포함된다. 매주 파이프라인이 갱신하려면 재빌드·재기동이 필요해 `content-draft`가 누리는 "커밋만 하면 즉시 반영" 이점이 없다. 이를 글로서리·FAQ와 같은 원리로 바꾼다.

- 신규 파일 `web/content/news-hook.json` (frontmatter 없는 단일 JSON, 스키마):
  ```json
  {
    "updated_at": "2026-08-27",
    "source_url": "https://...",
    "kicker": "속보",
    "body_ko": "...",
    "body_en": "...",
    "guide_ko": "...",
    "guide_en": "..."
  }
  ```
- `NewsHook.tsx`는 서버 컴포넌트에서 이 파일을 매 요청 시 읽어 렌더링한다(글로서리 목록이 `web/content/glossary/*.md`를 동적 렌더하는 것과 동일 원리 — 상세는 구현 플랜에서 기존 콘텐츠 로더 재사용 여부 확인).
- 초기값은 기존 신진서-카타고 문구를 그대로 이 파일에 옮겨 심어, 마이그레이션 첫 주는 화면 변화가 없게 한다.
- `ko.json`/`en.json`의 `home.newsHook.*` 키는 제거한다(중복 소스 방지).

### 안전장치 요약

| 장치 | 방지하는 실패 |
|---|---|
| 출처 URL 필수 | 근거 없는 주장 게시 |
| 사실검증 서브에이전트 | 사실과 다른 과장·오역 게시 |
| "뉴스 없으면 유지" 게이트 | 소재 조작·억지 생성 |
| 동일 `source_url` 중복 게시 방지 | 같은 사건을 매주 재탕 |
| 기사 원문 인용 금지(자기 서술만) | 저작권 재현 문제 |
| 범위 제한(바둑·프로기사·AI 대국만) | 브랜드와 무관한 화제 유입으로 신뢰도 손상 |

자율 게시(사람 승인 없음)로 진행하기로 확정했으나, 위 게이트들이 실질적인 승인 절차를 대신한다. 첫 몇 주간 게시 결과를 오케스트레이터 다이제스트로 계속 관찰하고, 오탐(부적절한 소재 게시)이 발생하면 즉시 🟡(사람 승인)로 격상한다.

### 운영 통합

- `ops/run-news-hook.sh` — `run-content-draft.sh`와 동일 구조(PATH 보정, `ops.env` 로드, 실행 로그).
- `docs/ops/news-hook-prompt.md` — 위 5단계를 절차로 명시. `autonomy-policy.md` 참조, 사실검증 실패/뉴스 없음 시 종료 조건 명시.
- `~/Library/LaunchAgents/com.inkbaduk.news-hook.plist` — 주 1회. `content-draft`(토 02:00, 수 02:00)와 겹치지 않는 시각으로 배치(예: 일 03:00) — 정확한 시각은 구현 시 기존 cron 슬롯과 충돌 확인 후 확정.
- `docs/ops/state/jobs/news-hook.json` — `content-draft.json`과 동일 스키마(`job/status/summary/at`). 오케스트레이터의 "자동화" 다이제스트 행에 합산.
- `docs/ops/state/log/news-hook-runs.log`, `.err.log`, `.out.log` — 기존 job들과 동일 로그 패턴.
- watchdog stale 감지 대상에 `news-hook`도 포함되는지 확인(기존 watchdog 설정이 `state/jobs/*.json`을 범용으로 스캔한다면 자동 포함될 가능성 높음 — 구현 시 확인).

## 검증이 필요한 기술 리스크

1. **헤드리스 WebSearch 가용성** — `claude -p --dangerously-skip-permissions` 세션에서 WebSearch 도구가 실제로 동작하는지 미검증. 구현 플랜의 첫 태스크로 최소 스파이크를 돌려 확인한다. 동작하지 않으면 firecrawl(MCP) 또는 특정 바둑 매체 RSS 폴링으로 대체를 검토한다.
2. **콘텐츠 로더 재사용 가능 여부** — 글로서리가 쓰는 동적 파일 읽기 유틸이 있다면 재사용하고, 없다면 `news-hook.json`에 맞는 최소 로더를 새로 만든다(과도한 추상화 금지).

## 실행·검증

1. WebSearch 헤드리스 가용성 스파이크.
2. `news-hook.json` 스키마 확정 + `NewsHook.tsx` 동적 렌더 전환(기존 신진서 문구로 초기화, 화면 무변화 확인) + `ko.json`/`en.json`의 구 키 제거.
3. `ops/run-news-hook.sh` + `docs/ops/news-hook-prompt.md` + launchd plist 작성.
4. 수동 1회 드라이런(`bash ops/run-news-hook.sh`)으로 "뉴스 없음 → 유지" 경로와 실제 게시 경로(과거 신진서 사례로 모의) 둘 다 확인.
5. `npm run build`·`lint`·`type-check`·기존 테스트 통과. design-token-guardian + visual-qa(홈, 라이트/다크)로 렌더 회귀 확인.
6. launchd 등록 + `launchctl list`로 스케줄 확인.

## 성공 기준

- `news-hook.json` 갱신만으로 재빌드·재기동 없이 홈 화면에 반영됨.
- 사실검증 게이트가 출처 불일치 사례에서 게시를 실제로 막는지 최소 1개 시나리오로 검증됨.
- 몇 주간 관찰 후에도 부적절한 소재 게시가 없으면 자율 게시 유지, 문제 발생 시 🟡로 격상하고 사람에게 보고.
