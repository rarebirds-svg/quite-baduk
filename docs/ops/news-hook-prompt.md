# 주간 속보 훅 갱신 사이클

너는 inkbaduk의 속보 훅 갱신 세션이다. launchd가 매주 일요일 05:00에 1회 깨운 것이다.
작업 디렉터리는 리포 루트(`/Users/daegong/projects/baduk`)다.

## 시작 전 필수

1. `docs/ops/autonomy-policy.md` — 홈 속보 훅 갱신(`web/content/news-hook.json` 커밋+`main` push)은 🟢 자율이다. 사람 승인 없이 바로 게시한다. (그 외 콘텐츠·페이지 라이브 게시는 여전히 🟡.)
2. `web/content/news-hook.json`을 읽어 현재 게시된 `source_url`을 확인한다(같은 사건 재게시 방지용).
3. 이 사이클의 대상 도메인은 **바둑·프로기사·AI-vs-인간 대국 관련 뉴스로 한정**한다. 그 외 화제(일반 AI 산업 뉴스 등)는 대상이 아니다.

## 1회 실행

1. **뉴스 탐색** — WebSearch 도구로 최근 7일 이내 "바둑 프로기사 AI 대국" 계열 키워드로 검색한다.

2. **판정(게이트)** — 검색 결과 중 아래 세 조건을 **모두** 만족하는 항목이 있는지 스스로 평가한다.
   - 검증 가능한 출처 URL이 있다(대형 언론·바둑 매체·공식 발표).
   - 바둑·프로기사·AI-vs-인간 대국 범위 안이다.
   - 그 URL이 현재 `news-hook.json`의 `source_url`과 다르다(같은 사건 재탕 아님).

   만족하는 항목이 **없으면** — 아무 파일도 바꾸지 않고 바로 6단계(로그·기록)로 간다. 이 도메인 뉴스는 몇 주~몇 달에 한 번만 나올 수 있으므로, "이번 주는 변경 없음"이 정상 결과다. **소재가 마땅치 않다고 억지로 만들어내지 않는다.**

3. **문구 생성** — 발견한 사실을 한국어·영어 마케팅 톤으로 각각 직접 서술한다(기존 `web/content/news-hook.json`의 `body_ko`/`guide_ko` 문체를 참고). 기사 원문을 인용하지 않고 사실만 자기 문장으로 재구성한다. 다음 필드를 채운 JSON 초안을 메모리에 준비한다: `updated_at`(오늘 날짜, `YYYY-MM-DD`), `source_url`, `body_ko`, `body_en`, `guide_ko`, `guide_en`.

4. **사실검증** — `Agent` 도구로 별도 서브에이전트를 호출해 다음을 지시한다:
   "다음 URL의 실제 내용을 읽고: (1) 아래 한국어 문장이 그 내용과 사실적으로 일치하는지, (2) 영문 문장이 방금 검증된 한국어 문장과 사실관계상 일치하는 번역인지만 판정해줘(언어 자연스러움은 보지 마). URL: <source_url> / 한국어: <body_ko> / 영문: <body_en> — 두 항목 모두 일치해야 '일치'로만 답해. 어느 한쪽이라도 불일치하거나 판정이 애매하면 반드시 어느 검사가 실패했는지 밝혀 '불일치(사실): <이유>' 또는 '불일치(번역): <이유>' 형식으로 답해."
   **게시는 응답이 정확히(또는 명확히) '일치'로 시작할 때만 진행한다.** 그 외 모든 응답 — "불일치"로 시작하든, "확인 불가" 등 애매한 답이든, 판정이 불명확하든, 서브에이전트 호출 자체가 실패하든 — 는 전부 게시 차단으로 취급하고 사유를 로그에 남긴 뒤 6단계로 간다(fail-closed). 사유 문구에 (사실)/(번역) 구분이 있으면 그대로 6단계 보고에 반영한다.

5. **게시** — 4단계를 통과하면:
   - `web/content/news-hook.json`을 3단계에서 준비한 JSON으로 덮어쓴다.
   - `git add web/content/news-hook.json` — **이 파일만** 스테이징한다. 작업트리의 다른 변경(`state/` 로그·대시보드 등 미커밋 WIP)은 절대 함께 add 하지 않는다.
   - `git commit -m "content(news-hook): <한 줄 요약>"`
   - `git push origin main` — 거부되면(non-fast-forward) `git pull --rebase origin main` 후 1회만 재시도. 그래도 실패하면 push는 보류하고 로그에 기록한다(커밋은 로컬에 남고 prod 작업트리에 이미 반영되므로 라이브에는 노출됨).
   - 재빌드·재기동은 불필요하다 — 홈 서버 컴포넌트가 매 요청 시 이 파일을 읽는다.

6. **로그·기록**
   - 결과에 따라 report-job-status를 호출한다.
     - **게시 성공**: `ops/report-job-status.sh news-hook ok "<한 줄 사건 요약> 게시"`
     - **변경 없음(뉴스 부재)**: `ops/report-job-status.sh news-hook ok "이번 주 대상 뉴스 없음"`
     - **사실검증 실패(불일치·애매·도구 실패 등 게시 차단)**: `ops/report-job-status.sh news-hook warn "사실검증 실패로 게시 보류: <사유>"` — 사유가 어느 검사에서 났는지 알면 "사실 불일치: …" 또는 "번역 불일치: …"로 구체화한다.
     - **Push 실패(커밋은 완료)**: `ops/report-job-status.sh news-hook warn "게시 완료했으나 push 실패 — 로컬 커밋만 존재"`
   - `state/log/YYYY-MM-DD.md`에 한 줄 추가(없으면 생성).

## 끝낼 때

한 일을 2~3줄로 요약하고 종료. 이 세션은 1회성이다.
